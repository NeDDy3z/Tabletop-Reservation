# 📔 Zpráva o projektu – Tabletop Reservations

---

## 1. Popis aplikace a struktura projektu
Tabletop Reservations je REST API pro správu **rezervací herních stolů a časových slotů** v podnicích zaměřených na deskové hry.  
Aplikace umožňuje provozovatelům nabízet dostupné termíny a hráčům si je rezervovat. Součástí je také **hodnoticí systém** uživatelů a podniků.

Systém podporuje role:
- **PLAYER** – vytváří rezervace a hodnotí ostatní uživatele / venues
- **PROVIDER** – spravuje vlastní venues, stoly a časové sloty
- **ADMIN** – globální správa aplikace

Autentizace probíhá pomocí **HTTP Basic Auth** (email + heslo).

---

### Struktura projektu

Projekt je rozdělen do několika standardních vrstev:

#### `model`
JPA entity reprezentující doménu aplikace:
- `User`, `Venue`, `GameTable`, `TimeSlot`
- `Reservation`, `Rating`, `DeskGame`, `DeskGameItem`, `Category`
- pomocné třídy (`RatingId`, `AbstractEntity`)
- enumy (`Role`, `ReservationState`)

#### `repository`
Datová vrstva nad `EntityManager`.
- `BaseRepository<T>` – společná CRUD logika
- konkrétní repository využívají **Named Queries** nebo **Criteria API**
- metody vracející kolekce vždy vrací prázdný seznam místo `null`

#### `service`
Business logika aplikace.
- validace vstupů
- změny stavů rezervací
- kontrola oprávnění
- transakční hranice (`@Transactional`)

#### `rest`
REST API vrstva.
- controllery (`@RestController`)
- request / response DTO
- mapování endpointů a HTTP kódů

#### `security`
Bezpečnostní logika:
- kontrola rolí
- helper metody (`isSelfOrAdmin`, `isOwnerOrAdmin`, …)

---

### Přehled endpointů

#### Users – `/rest/users`
- `GET /rest/users` (ADMIN) – seznam uživatelů
- `GET /rest/users/{id}` (SELF/ADMIN) – detail uživatele
- `POST /rest/users/register` – registrace uživatele
- `PUT /rest/users/{id}` (SELF/ADMIN) – úprava profilu
- `DELETE /rest/users/{id}` (ADMIN) – smazání uživatele

#### Venues – `/rest/venues`
- `GET /rest/venues` – seznam venues
- `POST /rest/venues` (PROVIDER) – vytvoření venue
- `PUT /rest/venues/{id}` (OWNER/ADMIN) – úprava venue
- `GET /rest/venues/{id}/timeslots/available` – dostupné sloty

#### GameTables – `/rest/gametables`
- `POST /rest/gametables` (PROVIDER) – vytvoření stolu
- `POST /rest/gametables/{id}/timeslots` – přidání slotu

#### Reservations – `/rest/reservations`
- `POST /rest/reservations` (PLAYER) – vytvoření rezervace
- `PUT /rest/reservations/{id}/confirm` (PROVIDER) – potvrzení
- `PUT /rest/reservations/{id}/cancel` – zrušení rezervace
- `PUT /rest/reservations/{id}/complete` – dokončení rezervace

#### Ratings – `/rest/ratings`
- `POST /rest/ratings` – vytvoření hodnocení
- `GET /rest/ratings/my` – hodnocení vytvořená přihlášeným uživatelem
- `GET /rest/ratings/{ratedId}` – hodnocení uživatele
- `GET /rest/ratings/venue/{venueId}` – hodnocení venue

## 2. Spuštění, testování a testovací data

Aplikace je testována pomocí REST API kolekcí připravených v nástroji **Hoppscotch**.
Tyto kolekce pokrývají hlavní aplikační scénáře, včetně správy uživatelů, rezervací, hodnocení, heren (venues), herních stolů a časových slotů.

### Spuštění testů

1. Spusťte aplikaci lokálně (viz kapitola *Instalace a spuštění*).
2. Otevřete nástroj **Hoppscotch**.
3. Importujte připravenou kolekci [testů](/src/main/resources/Tabletop%20Reservations%20API%20-%20Hoppschotch.json) (`.json` soubor).
4. Nastavte proměnnou `baseUrl` (např. `http://localhost:8080`).
5. Spusťte jednotlivé requesty nebo celé složky v doporučeném pořadí.

⚠️ **Poznámka:** Některé testy na sebe logicky navazují (např. vytvoření rezervace → hodnocení rezervace), proto je vhodné je spouštět ve stanoveném pořadí.

### Autentizace

Testy využívají **HTTP Basic Authentication**. 
Přihlašovací údaje testovacích uživatelů jsou definovány jako proměnné v testovací kolekci (např. `adminEmail`, `playerEmail`, `providerEmail`).
